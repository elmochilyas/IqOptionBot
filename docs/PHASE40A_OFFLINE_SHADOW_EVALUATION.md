# Phase 40A: Offline Shadow Evaluation Foundation

## 1. Executive Summary & Mission

Phase 40A establishes a reproducible, scientifically rigorous, and entirely offline foundation for candidate model shadow evaluation on `IqOptionBot`. Building upon the Phase 39 Offline Model Laboratory, this milestone provides the infrastructure to register frozen candidate models, execute leak-free point-in-time inferences, commit immutable append-only predictions before outcomes are known, resolve delayed outcomes chronologically, and evaluate candidate performance against rigorous statistical and economic benchmarks.

### Operational Constraints & Invariants
- **100% Offline Execution**: Zero live broker network calls, zero credentials, zero WebSocket connections, zero live observation, zero order execution, and zero practice account balance checks.
- **Evidence Integrity**: All existing historical collection sessions, including `data/extended_collection/collection_a20ad775b77d4f2bab787f540b2d6890` (8 verified candles), and Phase 38 prospective pilot artifacts remain bit-for-bit immutable.
- **Separation of Inference and Outcome**: Predictions are committed to an append-only journal strictly prior to outcome resolution. The prediction engine cannot access future candles, and outcome resolution cannot alter or overwrite committed predictions.
- **Frozen Execution Authority**: All candidate models registered for shadow evaluation are marked `execution_authority = "NONE"`. No model can be promoted to live execution based on offline replay performance alone. Edge classification fails closed (`NO_RELIABLE_EDGE_DETECTED`).

## 2. Architectural Overview & Component Structure

The Phase 40A shadow evaluation system resides in `src/iqoption_research/shadow/` and integrates into the CLI (`src/iqoption_research/cli/commands/shadow_cmd.py`) and Tkinter desktop workstation (`src/iqoption_research/desktop/shadow_panel.py`):

```
src/iqoption_research/shadow/
├── __init__.py           # Package exports
├── registry.py           # ShadowModelRegistry & FrozenRegistrationRecord
├── engine.py             # ShadowPredictionEngine, PredictionOutput, & InferenceDiagnostic
├── journal.py            # ShadowPredictionJournal, ShadowPredictionRecord, & OutcomeEventRecord
├── evaluator.py          # ShadowOutcomeEvaluator, EvaluationSummary, & BaselineComparison
└── replay.py             # HistoricalReplayEngine, ReplayConfig, & ReplayResult
```

### Component Flow
```
[Candidate Model Bundle] ──> [ShadowModelRegistry] ──> Frozen Registration (registry.json)
                                     │
                                     ▼
[Historical Candles]     ──> [ShadowPredictionEngine] ──> Leak-Free Prediction (UP/DOWN/SKIP)
                                     │
                                     ▼ (Committed BEFORE outcome known)
                             [predictions.jsonl]
                                     │
[Future Maturity Candle] ──> [ShadowOutcomeEvaluator] ──> Delayed Resolution (WIN/LOSS/TIE)
                                     │
                                     ▼ (Committed upon maturity)
                              [outcomes.jsonl]
                                     │
                                     ▼
                             [session.json] (Self-Digest & Scientific Summary)
```

## 3. Frozen Candidate-Model Registration (`registry.py`)

The `ShadowModelRegistry` provides immutable registration and tamper-evident loading of verified candidate AI models generated by the Phase 39 Model Laboratory:

### A. Verification and Containment
- Evaluates candidate bundles directly via `ModelLaboratory.load_candidate_bundle()`.
- Validates that candidate paths reside strictly within authorized directories (`data/candidate_models/`), preventing directory traversal or untrusted pickle deserialization.
- Re-verifies cryptographic checksums:
  - Manifest self-digest (`manifest_sha256`) against canonical serialized JSON.
  - Model bundle checksum (`bundle_sha256`) against actual `bundle.joblib` bytes on disk.
- Extracts and validates data cutoff timestamp (`data_cutoff_ts`), feature names, model family, and baseline indicators.

### B. Configuration Freezing
- Freezes the decision threshold $\tau$ (parameterized, defaulting to model training configuration or explicit operator override $\in [0.50, 1.0]$).
- Freezes probability calibration method (e.g. isotonic, sigmoid, or none) and feature schema.
- Assigns an immutable evaluation identifier (`evaluation_id`, e.g. `eval_<model_id>_<hash>`) and registration timestamp.
- Persists registry records in `data/shadow_eval/registry.json` with an atomic rename and top-level self-digest `registry_sha256`.

### C. Mutation Rejection
- Any attempt to re-register, retrain, mutate, or substitute an existing registered model fails closed with `ModelMutationError`.
- If an on-disk bundle file or manifest is tampered with post-registration, `load_frozen_bundle()` fails closed with `ModelVerificationError`.

## 4. Shadow Prediction Engine (`engine.py`)

The `ShadowPredictionEngine` executes point-in-time inference on finalized historical candles using frozen candidate models under strict causal guarantees:

### A. Point-in-Time Invariant
- Inference takes an explicit chronological sequence of candles and an optional `decision_ts`.
- **Zero Future Data Leakage**: Enforces that no candle close timestamp (`to_ts`) exceeds `decision_ts`. Any candle closing strictly after `decision_ts` raises `PointInTimeViolationError`.
- **Chronological Sequence**: Validates that candles are ordered chronologically without inversion.

### B. Causal Warmup & Continuity
- Requires a minimum causal warmup window (default: 21 bars) to populate lag features and moving averages. Sequences with fewer bars raise `WarmupIncompleteError`.
- Detects unfinalized candles (`is_complete=False`) and raises `IncompleteCandleError`.
- Validates temporal continuity via `CausalFeaturePipeline(enforce_temporal_continuity=True)`. Missing bars or gaps exceeding 60 seconds raise `DiscontinuousDataError`, completely preventing feature computation across unverified or discontinuous intervals.

### C. Decision Thresholding & Abstention
- Computes causal features using data up to the cutoff timestamp $t$.
- Generates a deterministic 16-character SHA-256 fingerprint over sorted feature key-value pairs (`feature_fingerprint`).
- Evaluates raw probabilities $P_{\text{raw}}$ and applies the frozen probability calibrator.
- Evaluates directional decision against the frozen confidence threshold $\tau$:
  - $\text{Decision} = \text{UP}$ if $P(\text{UP}) \ge \tau$
  - $\text{Decision} = \text{DOWN}$ if $P(\text{DOWN}) \ge \tau$
  - $\text{Decision} = \text{SKIP}$ (Abstain) if $\max(P(\text{UP}), P(\text{DOWN})) < \tau$
- For abstentions and non-prediction events, records the explicit reason without fabricating synthetic trades.

## 5. Immutable Prediction Journal (`journal.py`)

The `ShadowPredictionJournal` maintains an append-only, tamper-evident operational log across two distinct files in `data/shadow_eval/sessions/<session_id>/`:

### A. Two-Phase Log Architecture
1. **Prediction Log (`predictions.jsonl`)**:
   - Every inference (trade decision or abstention) is committed to disk **prior** to any future price observation or outcome evaluation.
   - Records: `session_id`, `prediction_id`, `model_id`, `artifact_hash`, `symbol`, `timeframe`, `feature_cutoff_ts`, `probabilities`, `decision`, `confidence_threshold`, `prediction_horizon_bars`, `expected_maturity_ts`, `feature_fingerprint`, and runtime diagnostics.
2. **Delayed Outcome Log (`outcomes.jsonl`)**:
   - When the maturity timestamp $t_{\text{maturity}}$ arrives, the independent outcome evaluator writes an immutable `OutcomeEventRecord` to `outcomes.jsonl`.
   - Links by `prediction_id` without modifying or rewriting the historical prediction entry in `predictions.jsonl`.

### B. Integrity & Crash Recovery
- **Duplicate Prevention**: Fails closed with `DuplicatePredictionError` on any attempt to submit multiple predictions for the same model and cutoff timestamp `(model_id, feature_cutoff_ts)`.
- **Crash Recovery**: If execution is interrupted, `ShadowPredictionJournal` automatically reconstructs complete in-memory indices upon re-instantiation by scanning `predictions.jsonl` and `outcomes.jsonl`.

## 6. Delayed Outcome Evaluation (`evaluator.py`)

The `ShadowOutcomeEvaluator` resolves outcomes for committed predictions strictly once maturity candles become available:

### A. Delayed Maturity Invariant
- Predictions with horizon $H=1$ bar maturing at $t_{\text{maturity}} = t_{\text{cutoff}} + 60$ cannot be resolved until a candle with $t_{\text{candle\_to}} \ge t_{\text{maturity}}$ is received.
- Early outcome evaluation attempts return 0 resolved predictions.

### B. Outcome Classification
- **RESOLVED_WIN**: Direction matched market price return ($P_{\text{close}} > P_{\text{open}}$ for UP, $P_{\text{close}} < P_{\text{open}}$ for DOWN).
- **RESOLVED_LOSS**: Direction conflicted with market price return.
- **RESOLVED_TIE**: Open price equals close price ($P_{\text{close}} == P_{\text{open}}$).
- **SKIPPED_ABSTAIN**: Model chose not to trade due to confidence below threshold.
- **INVALID_DISCONTINUITY**: An unexpected gap or missing candle occurred before maturity.

### C. Statistical & Economic Metrics
- **Selective Win Rate (All Trades)**: Calculated across all trades taken, including ties: $W = \frac{\text{Wins}}{\text{Wins} + \text{Losses} + \text{Ties}}$.
- **Selective Win Rate (Decisive Trades)**: Calculated strictly conditional on decisive (non-tie) outcomes: $W_{\text{decisive}} = \frac{\text{Wins}}{\text{Wins} + \text{Losses}}$.
- **Tie Rate**: Proportion of trades resulting in an exact price tie (refund): $T_{\text{rate}} = \frac{\text{Ties}}{\text{Total Trades}}$.
- **Coverage & Abstention Rates**: $\text{Coverage} = \frac{\text{Trades}}{\text{Resolved}}$, $\text{Abstention} = \frac{\text{Skips}}{\text{Resolved}}$.
- **Full Directional Accuracy**: Proportion of correct directional classifications across all observations.
- **Brier Score Calibration**: Mean squared difference between predicted probabilities and binary outcomes: $\text{Brier} = \frac{1}{N} \sum (P(\text{UP}) - Y)^2$.
- **Wilson 95% Score Confidence Interval**: Exact binomial confidence interval $[L, U]$ on selective win rate.
- **Break-Even Win Rate (Decisive)**: Decisive break-even hurdle from assumed payout rate $P$ (default 85%): $W_{\text{be, decisive}} = \frac{1}{1 + P} = 54.05\%$.
- **Break-Even Win Rate (All Trades)**: Accounts for refunded ties: $W_{\text{be, all}} = \frac{1 - T_{\text{rate}}}{1 + P} = \frac{1 - 15/397}{1.85} = 52.01\%$.
- **Tie-Aware Simulated Expectancy**: Calculated from actual simulated P&L where ties refund 0:
  $$\text{PnL} = \text{Wins} \cdot P - \text{Losses} \cdot 1.0 + \text{Ties} \cdot 0.0$$
  $$E = \frac{\text{PnL}}{\text{Total Trades}} \cdot 100\% = \frac{188 \cdot 0.85 - 194 \cdot 1.0}{397} \cdot 100\% = \frac{-34.2}{397} \cdot 100\% = -8.61\%$$
  *(Corrected from legacy formula which counted refunded ties as losses resulting in -12.39%).*
- **Hindsight-Free Reference Baselines**:
  - Compares candidate metrics against Majority Class and Random Uniform baselines on the **identical observation population** (`trade_preds`, $N=397$).
  - **No Fabricated Defaults**: Baseline statistics are obtained strictly from an authentic, verified pre-evaluation training source or a separately registered authentic majority-class baseline (`is_baseline=True`). If verified baseline statistics are unavailable, `baseline_comparison_available` is marked `False`, preventing any baseline-superiority claim.
  - Parameters are cryptographically bound to source evidence (`baseline_source_model_id`, `baseline_source_sha256`).
  - Unverifiable legacy records are classified explicitly as `LEGACY_UNVERIFIED_BASELINE` with `baseline_comparison_available = False`.
  - The majority class baseline direction is permanently frozen from pre-cutoff training metadata (`training_majority_direction = "DOWN"`, `training_majority_prob_up = 0.4691`). The evaluator never derives a baseline direction from evaluation period labels.
  - Modifying future evaluation outcomes leaves the baseline's predictions and probabilities invariant.
  - Every baseline comparison explicitly reports `matched_sample_count`, `decisive_sample_count`, and `tie_count`.

## 7. Historical Replay Engine & Acceptance Verification (`replay.py`)

The `HistoricalReplayEngine` coordinates chronological playback of historical market data through the prediction engine and delayed outcome evaluator:

### A. Memory-Bounded Lookback Buffer
- Retains only a sliding window of historical candles (lookback buffer $\le 60$ bars) in memory.
- Safe for execution on resource-constrained systems (safe for 16 GB RAM).
- Supports cooperative cancellation via `cancel_token` and progress reporting.

### B. Multi-Tier Model Exposure Boundaries & Scientific Verdicts
- Verified exposure-boundary metadata distinguishes:
  - **Training Cutoff** (`training_cutoff_ts` / `data_cutoff_ts`): Last timestamp included in model parameter fitting.
  - **Validation & Calibration Exposure** (`validation_cutoff_ts`): Last timestamp included in probability calibrator fitting (e.g. isotonic regression) and threshold selection.
  - **Holdout Evaluation Exposure** (`holdout_cutoff_ts`): Last timestamp included in holdout test evaluation.
  - **Complete Source Snapshot Boundary** (`source_snapshot_end_ts`): End timestamp of the source research dataset snapshot.
  - **Genuine Prospective Observation**: Can only occur strictly post-registration on streaming market data.
- The replay engine compares data start against all exposure tiers:
  - Overlap with training -> `OVERLAPS_TRAINING_EXPOSURE` (`is_functional_test = True`).
  - Overlap with validation/calibration -> `OVERLAPS_VALIDATION_EXPOSURE` (`is_functional_test = True`).
  - Overlap with holdout -> `OVERLAPS_HOLDOUT_EXPOSURE` (`is_functional_test = True`).
  - Overlap with source snapshot -> `OVERLAPS_SOURCE_SNAPSHOT_EXPOSURE` (`is_functional_test = True`).
  - Start after snapshot end -> `POST_SNAPSHOT_HISTORICAL_REPLAY` (`is_functional_test = False`, but strictly `OFFLINE_REPLAY`).
- **All historical replays remain retrospective**: Even when a replay begins after the training cutoff or source snapshot, historical replays are retrospective (`evidence_class == "OFFLINE_REPLAY"`) and never claim prospective evidence.
- For all offline replays, `has_statistical_edge` remains strictly `False` and project disposition remains `NO_DEMONSTRATED_EDGE`. Candidate models are not automatically promoted.

### C. Evidence Storage Durability, Replay Diagnostics & Provenance
- **Self-Digest Integrity Verification**: `ShadowModelRegistry` verifies the top-level `registry_sha256` upon initialization and reading unconditionally (even on registries with zero records), failing closed with `RegistryIntegrityError` if tampering or missing digest is detected.
- **Fail-Closed Journal Recovery**: `ShadowPredictionJournal` rejects corrupt, malformed, orphaned, duplicate, or conflicting records on startup (`JournalCorruptionError`, `OrphanedOutcomeError`, `DuplicateOutcomeError`, `ConflictingOutcomeError`).
- **Disk Durability**: Append operations enforce immediate persistence via `f.flush()` and `os.fsync(f.fileno())`.
- **Path Traversal Protection**: Session and model identifiers are validated across CLI, engine, and journal via `validate_storage_identifier()`, rejecting directory traversal attempts (`..`, `/`, `\`).
- **Idempotency & Session Protection**: Attempts to reuse completed session IDs fail closed with `SessionAlreadyCompletedError`.
- **Diagnostic Failure Tracking**: Prediction engine errors are tracked in `prediction_failures_count` and diagnostics, strictly distinguished from model abstentions (`SKIP`).
- **Provenance Timestamps**: Distinguishes theoretical candle close (`feature_cutoff_ts`), simulated decision time (`simulated_decision_ts`), actual wall-clock execution time (`executed_wall_clock_utc`), and market feed availability (`broker_availability_type = "HISTORICAL_THEORETICAL_CLOSE"`).
- **Session Verification**: `verify_session()` computes cryptographic checksums over `predictions.jsonl` and `outcomes.jsonl`. Rejects missing or inconsistent outcomes journals whenever metadata claims recorded outcomes or specifies a journal digest, while handling genuinely empty journals explicitly. Legacy sessions without checksums are preserved without modification and classified as `LEGACY_UNVERIFIED_EVIDENCE`.

## 8. Desktop Research Workstation Integration (`shadow_panel.py`)

A dedicated "Shadow Evaluation" panel is integrated into the Tkinter desktop workstation (`src/iqoption_research/desktop/app.py`):

### A. Subtab Capabilities
1. **Frozen Candidates**:
   - Displays all registered frozen candidate models in a treeview.
   - Shows model ID, family, baseline status, confidence threshold, training cutoff, bundle SHA-256, and laboratory verdict.
   - Detail view displays feature schema, calibration method, and research disclaimers.
   - Includes quick-register action to register verified models from the laboratory.
2. **Historical Replay**:
   - Configures model selection, dataset snapshot selection, max candles, lookback bars, and assumed payout rate.
   - Executes offline historical replay on background threads via `ThreadPoolExecutor` without blocking Tkinter UI responsiveness.
   - Displays live progress bar and status label with cooperative cancellation (`Cancel Replay`).
   - Renders formatted replay evaluation summaries, baseline comparisons, and statistical verdicts.
3. **Prediction Journal**:
   - Inspects committed sessions (`sreplay_*`).
   - Displays summary metrics: Total Predictions, Resolved, Pending, Trades Taken, Win Rate, and Wilson CI.
   - Interactive treeview listing individual predictions with timestamp, decision (UP/DOWN/SKIP), confidence probabilities, cutoff price, maturity price, outcome status, and simulated PnL.

### B. Safety Guarantee
- Prominent orange warning banner: `OFFLINE RESEARCH ONLY | ZERO BROKER NETWORK | NO DEMONSTRATED EDGE | NO LIVE EXECUTION AUTHORITY`.
- **Zero Live Trading Controls**: No broker connect button, no order placement trigger, and no execution credentials interface exists within the panel.

## 9. Blockers & Prerequisites for Prospective Live Shadowing

Future prospective live shadow observation remains strictly blocked until the following milestones are formally approved:
1. **Supervised Live Collector Acceptance (PR #51)**: Completion of operator-supervised live acceptance testing for Research Workstation V2 under market open conditions.
2. **Model Laboratory Acceptance (PR #52)**: Independent scientific acceptance of Phase 39 Model Laboratory offline dataset preparation and candidate training.
3. **Out-of-Sample Independent Prospective Data**: Genuine prospective shadow observation requires fresh streaming market data collected after the candidate model's data cutoff timestamp (`data_cutoff_ts`).
4. **Explicit Operator Authorization**: Prospective live observation requires affirmative operator opt-in with strict read-only session tokens and zero automated execution permissions.
